# 在新电脑上安装

安装程序只有一个窗口。它会检查自身，向你显示安装位置以及它将设置的所有内容，并且只在你单击**安装**时才进行安装。本页使用屏幕上的文字，从上到下逐一介绍这个窗口。

<a id="before-you-start"></a>

## 开始之前

- **复制整个安装程序**。如果生成时除了 `.exe` 之外还得到了一个 `.wamdata` 文件，请将两者复制到同一个文件夹中，并保留它们的名称。请参阅[大型应用](Big-Apps)。
- **只运行你信任的安装程序**。安装程序以完整的[管理员权限](Glossary#administrator-rights)运行。请像对待任何其他程序一样对待它：只有当它是你自己生成的，或者来自你信任的人时，才运行它。请参阅[隐私和安全](Privacy-and-Security)。
- **你需要此电脑上的管理员权限**，窗口还需要 [Direct3D 12](Glossary#direct3d-12)。没有 Direct3D 12 时，你仍然可以从命令提示符安装。请参阅[命令行](Command-Line)。

<a id="open-it"></a>

## 打开安装程序

双击安装程序。Windows 会显示 [UAC 提示](Glossary#uac-prompt)。除非生成安装程序的人对它进行了签名，否则安装程序是未签名的，因此提示通常显示**未知发布者**。这是正常的。请参阅[隐私和安全](Privacy-and-Security#signing)。

窗口“WinAppMigrator 安装程序”（“重新安装在另一台电脑上捕获的应用”）会立即打开，无论安装程序有多大。在检查其整个程序包的[哈希](Glossary#hash)时，它显示“正在检查安装程序…”。这需要读取整个程序包，因此大型安装程序需要一段时间。从这时起，安装程序会让它自己的文件保持打开状态，如果有数据文件，数据文件也一样，因此在窗口打开期间，两者都无法被更改或替换。

检查可能会在此停止，并显示一条红色消息。常见的有：

- 安装程序已损坏，或在生成后被更改：请从生成它的位置重新复制。
- 它的数据文件缺失，或者不是正确的文件：请将两个文件重新复制到同一个文件夹中。
- “此安装程序的程序包无法在此电脑上使用”，例如因为应用的程序是为另一种处理器生成的，或者需要较新版本的 Windows。没有进行任何更改。

所有这些情况都在[疑难解答](Troubleshooting#installing)中有说明。

检查通过后，窗口的标题会变为“安装”加上应用的名称。

<a id="its-language"></a>

### 安装程序的语言

安装程序使用其所运行的电脑的语言，而不是生成它的电脑的语言：如果 Windows 的显示语言是 WinAppMigrator 支持的 24 种语言之一，就使用该语言，否则使用英语。右上方的**语言**可以为本次运行更改语言。它列出的有关应用的内容，包括 WinAppMigrator 生成安装程序时写下的说明，也会使用该语言。使用 WinAppMigrator 0.6 或更早版本生成的安装程序会按原样以英语显示这些说明。[从命令行静默安装](Command-Line)时始终以英语回应，以便脚本读取。

<a id="the-app-and-where-it-goes"></a>

## 应用及其安装位置

第一张卡片显示应用的名称，其下方是发布者和版本，例如“Fabrikam Inc. · 1.7.3”。然后是：

| 行 | 显示的内容 |
| --- | --- |
| **捕获自** | 应用来源电脑的名称。仅当安装程序是在打开**用户数据**选项的情况下生成时才会出现。 |
| **安装程序** | 此安装程序文件是否已[签名](Glossary#signature)：先显示“正在检查其签名…”，然后显示“未签名：发布者未知”，或者“签名者：”加上签名者的名称。如果签名经不起检查，则改为显示一条红色消息：“此安装程序的签名无效”，括号中是 Windows 给出的原因，然后是“签名后它可能已被更改。” |
| **安装位置** | 应用将安装到的文件夹，旁边的**浏览**用于选择文件夹。初始值是应用在旧电脑上所在的文件夹。来自 32 位 Windows 的应用则初始为 `Program Files (x86)`，64 位 Windows 将 32 位应用存放在这里。如果该文件夹在这里无法使用，其下方会有一条红色通知说明原因。 |
| **所需空间** | 安装在该驱动器上需要多少空间，以及可用空间有多少，例如“C: 上最多 824.0 MB（可用 356.0 GB）”。它既计算解压缩后的程序包，也计算应用的文件。 |

第一行中的发布者名称来自程序包，因此任何人都可以随意填写。**安装程序**行来自 Windows，才是值得信任的那一行。

<a id="when-the-location-cannot-be-used"></a>

### 安装位置无法使用时

如果**安装位置**中的文件夹无法使用，其下方会有一条红色通知说明原因。在你选择其他文件夹之前，**安装**和**预览更改**一直显示为灰色，旁边的一行文字显示“在安装位置可以使用之前，‘安装’和‘预览更改’不可用。”

最常见的原因是该文件夹中已经有文件。只有当文件夹中的文件是之前由 WinAppMigrator 安装的，才会使用该文件夹，这样就绝不会替换其他应用的文件：

| 通知 | 含义 | 处理方法 |
| --- | --- | --- |
| 应用的名称，然后是“已安装在此文件夹中，因此这个副本不能安装到这里。” | 该应用已经安装在此电脑上，通常是由它自己的安装程序安装的：它的主程序位于该文件夹中，或者 Windows 的已安装应用列表显示它在那里。许多电脑上已有的应用常会出现这种情况，例如 Web 浏览器、媒体播放器或 Office。 | 先在 Windows 设置的**应用**中卸载此电脑上的副本，然后重新打开安装程序。或者在**安装位置**中输入一个新的空文件夹，将这个副本安装在它旁边。 |
| 另一个应用的名称，然后是“已安装在此文件夹中”，并说明此应用“不能安装到这里”。 | Windows 的已安装应用列表显示该文件夹中有另一个应用，例如另一个版本的 Office。 | 在**安装位置**中输入一个新的空文件夹。或者，如果你不再需要另一个应用，请先在 Windows 设置的**应用**中将其卸载，然后重新打开安装程序。 |
| “此文件夹中已有并非由 WinAppMigrator 安装的文件。” | 文件夹中有其他内容，但没有列出任何已安装的应用位于那里。这些内容可能属于其他应用。 | 在**安装位置**中输入一个新的空文件夹。如果这些文件是你已卸载的应用留下的，可以删除该文件夹，然后重新打开安装程序。 |

如果是其他原因，通知会显示“无法使用此文件夹：”、原因以及“请在上方输入其他文件夹。”这些原因是：

| 屏幕上显示的原因 | 处理方法 |
| --- | --- |
| “它必须是完整路径” | 输入以驱动器号开头的路径，例如 `C:\Program Files\Fabrikam Data Sync`。 |
| “它不能是整个驱动器” | 使用驱动器上的文件夹，而不是驱动器本身。 |
| “它不能是 Windows 文件夹” | 选择 `C:\Windows` 之外的文件夹。 |
| “其中并列存放着其他内容，因此应用需要使用其中的一个子文件夹” | 为应用添加一个文件夹，例如使用 `C:\Program Files\Fabrikam Data Sync`，而不是 `C:\Program Files`。 |
| “它是属于 Windows 的文件夹，或者其内容会自行运行或加载” | 选择一个普通文件夹。例如，“启动”文件夹会被拒绝。 |
| “它必须是此电脑驱动器上的普通路径” | [网络共享](Glossary#network-share)会被拒绝，Windows 会理解为其他东西的名称也会被拒绝。 |
| 说明它“是指向其他位置的链接，其他人可能能够更改它指向的位置” | 使用该[链接](Glossary#link)指向的文件夹。 |
| “它是安装保存其记录的位置” | 选择 `%ProgramData%\WinAppMigrator` 之外的文件夹。 |

如果文件夹中有文件，并且 WinAppMigrator 之前的某次安装**确实**记录在那里，安装程序将使用该文件夹，并发出警告：“此文件夹中已有文件。同名文件将被替换，卸载后会恢复。”

文件夹被接受后，窗口会替换同名的文件、注册表值、服务、任务、快捷方式或变量，就像[命令行](Command-Line#what---force-does)中的 `--force` 一样。已经属于其他应用的内容，例如它的服务或文件类型，仍然归该应用所有。

如果驱动器的空间看起来不足，会出现一条琥珀色说明，显示“此处可能没有足够的空间”以及所需的空间。程序包可以在其他驱动器上解压缩，但应用的文件仍须能放进这个驱动器。安装本身在开始之前会再次检查空间。

<a id="an-earlier-install-that-never-finished"></a>

### 之前未完成的安装

如果这些安装程序中的任何一个之前执行的安装因崩溃或断电而中断，会出现一条琥珀色说明：先是该应用的名称，然后是“之前的一次安装未完成。安装时会先撤消该次安装。”单击**安装**时会自动执行此操作。

<a id="what-this-sets-up-beyond-files"></a>

## 除文件之外还会设置的内容

这张卡片中的列表就是你单击**安装**时所同意的内容。在其标题下方显示：

> 所有这些操作都以管理员权限执行。如果安装失败，它所做的更改将被恢复，无法恢复的内容会告知你。你也可以稍后在“设置”的“已安装的应用”中撤消此安装。它替换的文件会恢复，它安装的运行时会保留。

每一行都有一个名称、右侧一个说明其类型的标签，以及一行说明其作用的文字。常规蓝色的标签表示普通项。**琥珀色**标签标记以完整权限运行的内容，例如以 LocalSystem 身份运行的服务、驱动程序，或允许入站连接的防火墙规则。请仔细检查这些内容。

如果列表为空，会显示“无：它只复制文件，以及应用自身注册表项中的设置。”

列表是针对框中的位置确定的。如果你更改了位置，它会短暂显示“正在确定在此位置将设置哪些内容…”，**安装**会等待。

| **环境变量** | [环境变量](Glossary#environment-variable) | “设置为”及其值 |

<a id="notes-and-what-is-left-out"></a>

### 说明和已排除的内容

在这些行下方，琥珀色说明会告诉你应当知道的事项，例如：

- 凭据没有放入安装程序，因此你可能需要重新输入；
- 生成时**许可证和激活数据**或**用户数据**选项处于关闭状态，因此安装程序中没有这些数据；
- 应用似乎依赖哪些[证书](Glossary#certificate)，这些证书从不会被安装；
- 生成安装程序的人排除了什么，又添加了什么；
- 应用可能无法在这里正常工作：“此应用原先位于 Windows 内部版本”后跟一个较新的版本号，或者 Windows 会“通过仿真运行”它的某些程序；
- 来自“文档”或“保存的游戏”的文件将“改为放在”安装文件夹“下名为 _external 的文件夹中”，因为此电脑上的这个文件夹位于你的配置文件之外。

然后，以琥珀色列出安全规则排除的每一项，并附上原因。前 20 项会完整显示。其余的位于“另有 … 项已排除”下，你可以展开查看。即使没有这些内容，安装的其余部分仍会继续进行。哪些内容会被拒绝以及原因，请参阅[安装程序中包含哪些内容](What-Goes-in-an-Installer#what-the-installer-refuses)。

如果程序包根本无法安装到所选位置，会显示一条红色消息“此程序包无法安装到此位置”及原因。

<a id="options"></a>

## 选项

只有当安装程序包含用户数据或许可证数据时，才会显示这张卡片。每个复选框最初都处于勾选状态。

| 选项 | 显示的内容 |
| --- | --- |
| **用户数据** | “开：设置、文档和保存的游戏将放入当前登录者的常用文件夹。关：全部放在安装文件夹下，且不会设置任何从中运行的内容。”如果安装程序说明了它包含谁的数据，下方会有一行文字显示“这里包含”该帐户“的数据”。 |
| **许可证** | “激活和许可证文件，以及保存许可证的注册表值。部分可能需要在此重新激活。” |

更改复选框会立即相应地更改上面的列表。

用户数据始终放入**当前登录 Windows 的人**的帐户，即使在 UAC 提示中输入的是另一个管理员的名称。如果安装程序无法确定登录的是谁，它会说明这一点，排除按用户的设置，并将用户数据放在安装文件夹下，而不是去猜测。如果该会话中没有人登录，用户数据和按用户的设置将归属于运行安装程序的帐户，它同样会说明这一点。

<a id="dependencies"></a>

## 依赖项

“此应用需要的内容，以及每项的提供方式。”每个[运行时](Glossary#runtime)都有一个标签：

| 标签 | 含义 |
| --- | --- |
| **已包含** | 在安装程序中。无需联网即可安装，但 DirectX End-User Runtime 除外，它的安装程序会从 Microsoft 获取它。其中只有 x64 Visual C++ 运行时在项目的测试中真正安装过。 |
| **通过 winget 安装：** 和一个 ID | 生成安装程序时无法下载它，因此安装程序使用 [winget](Glossary#winget)，这需要联网。项目的测试尚未运行过这种方式。 |
| **Windows 功能：NetFx3** | .NET Framework 3.5，作为 [Windows 功能](Glossary#windows-feature)启用。这可能需要联网。项目的测试尚未运行过这种方式。 |
| **Windows 内置** | .NET Framework 4，Windows 10 和 11 已经自带 |
| **随应用提供** | 应用自带一份副本 |
| **手动安装** | 这里没有它的安装程序。请自行安装。 |

如果没有任何依赖项，会显示“未检测到其他运行时依赖项。”请参阅[运行时](Runtimes)。

<a id="preview-changes"></a>

## 预览更改

**预览更改**会准确确定安装将执行的操作，但不做任何更改。它会检查空间是否足够，将程序包解压缩到一个专用文件夹，确定更改内容，然后再删除该文件夹。结果卡片的标题为“预览：尚未进行任何更改”，其中有**计划的更改**以及更改列表，服务、任务和快捷方式排在最前面。窗口会列出前 300 项，然后说明还有多少项。

预览不会检查每个文件的哈希。窗口打开时已经检查过整个程序包的哈希。

<a id="install"></a>

## 安装

在位置可以使用、并且列表是针对该位置确定的之前，**安装**一直显示为灰色。如果程序包根本无法安装到该位置，旁边会有一行文字显示“‘安装’不可用，因为此程序包无法安装到此位置。”，原因以红色显示在**除文件之外还会设置的内容**中。单击它时：

1. 它会再次确定列表。如果自你查看以来它将执行的操作发生了变化，它不会安装任何内容，而是显示新的列表，并显示“在此处将执行的操作已发生变化，因此未安装任何内容。请查看下面的列表，如果符合你的要求，请再次单击‘安装’。”
2. 它检查它要写入的每个驱动器上是否有足够的空间。
3. 它将程序包解压缩到只有管理员才能使用的文件夹，并在解压缩每个文件时检查其哈希。
4. 它进行安装，并在每项更改之前先将其写入[更改记录](Glossary#journal)，以便可以撤消。
5. 它读回安装的每个文件并检查其哈希。
6. 它启动设置为自动启动的服务。

在底部，你可以看到它正在做什么、计数（如果有）、已用时间、进度条以及**取消**。你可能看到的步骤有“正在准备…”、“正在解压缩”、“正在检查程序包”、“正在撤消之前未完成的安装”、“正在安装运行时”、“正在复制文件”、“正在设置服务”、“正在设置驱动程序”、“正在写入注册表设置”、“正在还原许可证数据”、“正在设置计划任务”、“正在创建快捷方式”、“正在设置环境变量”、“正在将应用添加到‘设置’”和“正在检查已安装的内容”。

**取消**会显示“将在当前步骤完成后取消…”，然后显示“正在恢复已更改的内容”。在安装过程中关闭窗口与单击**取消**的效果相同：窗口会一直保留，直到所有内容都已恢复。如果尚未进行任何更改，它会显示“已取消。未进行任何更改。”

<a id="the-hash-check"></a>

## 哈希检查

安装程序会检查三次[哈希](Glossary#hash)：

1. **窗口打开时**：检查整个程序包的哈希。被截断的副本，或在生成后被编辑过的副本，在读取其中任何内容之前就会被拒绝。
2. **解压缩时**：在将任何内容写入其位置之前，检查每个文件的哈希。
3. **安装之后**：读回安装的每个文件并再次检查。

哈希可以发现损坏，以及没有同时更新哈希的人所做的更改。哈希无法证明安装程序是谁制作的。只有[签名](Glossary#signature)才能做到这一点。

<a id="the-result"></a>

## 结果

结果卡片显示在顶部，标题为“安装结果”。

| 消息 | 含义 |
| --- | --- |
| “应用已安装，并已通过哈希检查。” | 一切正常。如果规则排除了某些内容，它会加上“但不包括下面列为已排除的内容。” |
| “安装已取消，其所做的更改已恢复。” | 你取消了安装。 |
| “安装失败，其所做的更改已恢复。” | 某项操作失败。它所做的更改已恢复，但它安装的运行时除外。其下方以琥珀色列出的内容被保留了下来，并说明了原因，例如只有在电脑重启时才会删除的服务。 |
| “安装失败，且其所做的更改未能全部恢复。剩余的内容列在下面，下次安装时会再次尝试。” | 请阅读该列表。再次运行安装程序时会再次尝试恢复这些内容。 |
| “安装未正常完成。请查看下面的问题。” | 请阅读其下方的消息。 |

然后是三个磁贴：**已进行的更改**（失败后为**已恢复的更改**）、**警告**和**错误**。标签显示**程序包哈希有效**和**已安装的文件有效**，或者以红色显示**程序包哈希无效**和**已安装的文件无效**。最多显示五条警告，所有错误都会作为消息显示。“某个依赖项需要重启才能完成。请重启 Windows，然后启动应用。”表示某个运行时要求重启。

**更改**及其计数会打开已执行操作的列表，最多 300 项。如果安装未正常完成，会以**日志**显示其[日志](Glossary#log)的路径。

安装正常完成后，底部的按钮会变为**关闭**和**打开安装文件夹**。

<a id="where-things-end-up"></a>

## 内容最终的位置

- **程序文件**放在安装位置中。
- 勾选该复选框时，**用户数据**放到已登录帐户自己的 AppData、文档、保存的游戏中，以及 ProgramData 中。此电脑保存在你的配置文件之外的“文档”或“保存的游戏”文件夹不会被写入。这些文件会放在安装位置下的 `_external` 中，列表会首先说明这一点。取消勾选时，所有用户数据都放在安装位置下。
- **快捷方式**放到此电脑的桌面和“开始”菜单中：你的，或者所有人的（如果原来就在那里）。
- **Path** 只会添加应用的条目。其中的其他内容都不会更改。
- **其他应用在这里已有的内容仍归该应用所有**。已经属于其他应用的文件类型、链接类型、COM 类、服务、事件日志源、字体或类似内容会保持不变，安装程序会加以说明。例如，原本要打开 `http` 链接的应用，必须在“设置”中重新设为默认应用。
- **设置**中会添加该应用的条目，因此你可以像卸载其他应用一样卸载它。请参阅[撤消安装](Undoing-an-Install)。

<a id="common-reasons-it-refuses"></a>

## 常见的拒绝原因

| 你看到的内容 | 原因 | 处理方法 |
| --- | --- | --- |
| “此应用无法在此电脑上运行，因此未进行任何更改” | 它的程序是为另一种处理器生成的，或者需要较新版本的 Windows | 在与旧电脑匹配的电脑上安装 |
| “空间不足，因此未进行任何更改” | 它要写入的某个驱动器上没有足够的可用空间 | 释放空间，或选择其他驱动器上的位置 |
| “另一个安装或卸载正在运行” | 一次只能运行一个 | 等它完成后重试 |
| 某个文件“的名称会被此版本的 Windows 当作设备而不是文件打开” | 应用中有名为 `aux.h` 之类的文件，Windows 11 之前的 Windows 无法保存这种文件 | 在 Windows 11 上安装 |
| 某个数据文件夹（例如 `%AppData%`）位于链接之下 | 安装程序不会通过链接写入 | 取消勾选**用户数据**和**许可证**，然后在不包含它们的情况下安装 |

更多原因请参阅[疑难解答](Troubleshooting#installing)。
